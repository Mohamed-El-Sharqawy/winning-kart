# Research: Meta creative-asset API surface (fact sheet)

Ticket: #23. Scope: what Marketing API v21.0 (as used by `apps/api/src/platforms/meta/client.ts`) offers for fetching creative media at scale, and the rate-limit cost of each option.

Provenance: all claims below were verified against Meta developer documentation. developers.facebook.com blocks direct scraping, so pages were read via Wayback Machine snapshots captured Dec 2024 (v21.0/v22.0 renders of the same URLs). Where a snapshot rendered v22.0 the content is unchanged from v21.0 for the cited fields.

## Media-bearing fields on `act_<id>/adcreatives` and `ad.creative{...}`

- `GET /v21.0/act_<id>/adcreatives?fields=...` lists all creatives on the account with standard cursor paging (`limit` + `paging.cursors.after`). Hard cap: "Only returns 50,000 ad creatives, pagination past this is unavailable." Source: AdCreative node limits, [ad-creative].
- Documented media-bearing fields on the AdCreative node [ad-creative]:
  - `image_url` — "A URL for the image for this creative."
  - `thumbnail_url` — "URL for a thumbnail image for this ad creative." Dimensions controlled by the `thumbnail_width` / `thumbnail_height` request params, both default 64 px; a read example is shown in the docs.
  - `video_id` — "Facebook object ID for video in this ad creative." (ID only; no inline playable URL.)
  - `object_story_spec` — AdCreativeObjectStorySpec: `page_id` plus exactly one of `link_data`, `photo_data`, `video_data`, `text_data`, `template_data`. `template_data` is "The spec for products to enable catalog related experience" (the DPA/carousel template card); carousels are `link_data.child_attachments[]`, whose cards carry `image_hash`/`video_id`. May be null for creatives generated by boosting an Instagram post. Source: [object-story-spec], [ad-creative].
  - `effective_object_story_id` — "The ID of a page post to use in an ad, regardless of whether it's an organic or unpublished page post." This is the promoted post behind the creative, including carousel/DPA rendering.
  - Related: `object_story_id`, `object_type` (enum incl. `VIDEO`, `PHOTO`, `POST_DELETED`), `thumbnail_id`, `image_hash`, `status` (`ACTIVE|IN_PROCESS|WITH_ISSUES|DELETED`).
- On ads, `creative` is an AdCreative nested object [ad]; Graph field expansion [field-expansion] allows requesting creative sub-fields inline, e.g. `GET /act_<id>/ads?fields=id,name,creative{id,name,thumbnail_url,video_id,effective_object_story_id}` — one paged call returns ads plus their creative media fields. (`client.ts` already uses `creative{id,name}` this way.)

## Playable video source: the `<video_id>` node

- `GET /v21.0/<video_id>?fields=source,picture` [video]:
  - `source` — "A URL to the raw, playable video file."
  - `picture` — "The URL for the thumbnail picture of the video."
  - Caveat: the Video node doc carries the banner "This document refers to a feature that was removed after Graph API v3.2" (public video features), yet the field table above is still documented there and remains the read path for ad-account videos.
- `GET /<video_id>/thumbnails` returns VideoThumbnail nodes [video-thumbnails]: fields `id`, `height`, `width`, `scale`, `name`, `uri`, `is_preferred`. The doc states token requirements "App or Page" and permissions `pages_read_engagement`, `pages_show_list` (written for Page-owned videos; ad-account videos read with a Marketing API system-user token are the winning-kart case and are not separately documented).

## Rate-limit accounting (`x-business-use-case-usage`)

- All Marketing API requests fall under Business Use Case (BUC) rate limits, applied per ad account per use case: "all endpoints with the Ads Management business use case will share the total quota within the same ad account." Ads Insights is a separate pool (`type: ads_insights`). Source: [rate-limiting].
- Rolling one-hour formulas (per ad account) [rate-limiting]:
  - Ads Insights — standard access: `600 + 400 * active_ads - 0.001 * user_errors`; advanced access (Ads Management Standard Access): `190000 + 400 * active_ads - 0.001 * user_errors`.
  - Ads Management — standard access: `300 + 40 * active_ads`; advanced access: `100000 + 40 * active_ads`.
  - Throttling can also trigger on `total_cputime` / `total_time` percentages regardless of call count.
- `x-business-use-case-usage` response header [rate-limiting]: JSON keyed by business-object-id (the ad account id); each entry has `type` (`ads_management`, `ads_insights`, ...), `call_count`, `total_cputime`, `total_time` (percentages over the rolling hour), `estimated_time_to_regain_access` (minutes), `ads_api_access_tier`. Up to 32 objects per header. Docs best practice: when the limit is reached, stop calling; check this header to see how close the account is and when to resume.
- Throttled calls return error code 80004: "There have been too many calls to this ad-account" [ad-creative].
- Relative cost of listing vs expanding: Meta does not publish per-endpoint or per-field weights. Accounting is per API call (one paginated GET = one counted call, regardless of how many `fields` are requested); heavier field sets instead push `total_cputime`/`total_time` (inference from [rate-limiting] + [batch], not a documented table). So `act_<id>/ads?fields=...,creative{...}` (N pages) costs the same call count as the ads listing alone, while a separate `act_<id>/adcreatives` listing adds its own page count to the same ads_management pool. Listing `adcreatives` account-wide also enumerates unused creatives that per-ad expansion never would.

## Graph Batch API

- `POST /?batch=[...]` accepts up to 50 requests per batch [batch]. Independent operations run in parallel; response order matches request order; each sub-request may carry its own access token.
- Crucial accounting fact: "Each call within the batch is counted separately for the purposes of calculating API call limits and resource limits. For example, a batch of 10 API calls will count as 10 calls." So batching reduces HTTP connections and latency, not BUC usage.
- Constraints [batch]: "Batch requests cannot include multiple Adsets under the same Campaign"; large batches may time out and return a partially-completed batch (unsuccessful sub-responses are `null`; retry them); per-sub-request errors don't fail the batch.

## Expiry of Meta CDN URLs (thumbnail_url, video source)

- Documented statements:
  - AdImage.`url` is "A temporary URL which the image can be retrieved at. Do not use this URL in ad creative creation." `url_128` is likewise temporary; in contrast `permalink_url` is "A permanent URL of the image." Source: [ad-image].
  - AdCreative preview iframes: "The API returns an iframe, which is only valid for 24 hours." Source: [previews].
- NOT documented anywhere I could find: the exact signature lifetime of `thumbnail_url` on a creative and of video `source` URLs. Community reports put them in the "hours" range and note URLs die with 403/expired-signature errors. Treat as unverified; the safe engineering stance is that any stored CDN URL must be re-fetched from the Graph API on demand.

## Insights `thumbnail_data`

- Absent from current primary docs: not present in the Ads Insights API pages, the v22.0 Insights Result node reference, the ad/ad-account insights edge references checked (see sources). It is a legacy/community-known field: requesting `fields=thumbnail_data` at `level=ad` on the insights edge returns `{url, width, height}` for the ad's thumbnail. Unverified from primary sources; do not build on it.

## Ads Manager deep links

- No official documentation found for Ads Manager URL parameters (`act=`, `selected_ad_ids=`, ...). Community-established formats (unverified): `https://www.facebook.com/adsmanager/manage/campaigns?act=<account_id_without_act_>&selected_ad_ids=<ad_id>[,<ad_id>...]` (comma-separated ids select multiple ads; `business.facebook.com` host variant also works). Treat as best-effort, verify manually per environment.

## Unverified / not established from primary sources

- TTL/signature lifetime of creative `thumbnail_url` and video `source` URLs (only "temporary" is documented, for AdImage).
- Insights `thumbnail_data` field shape and availability in v21.0.
- Ads Manager deep-link parameter formats.
- Per-endpoint/per-field rate-limit cost weights (Meta publishes none; call counting is per request).

## Implications for winning-kart

- Fold creative media fields into the ads listing (`creative{id,name,thumbnail_url,video_id,effective_object_story_id,...}`) instead of the separate account-wide `getCreativeDetails` pass: same call count for pagination, no second endpoint to page, no 50k-cap exposure, and unused creatives never fetched. Keep `act_<id>/adcreatives` only if the account-wide library itself is a product surface.
- Pass `thumbnail_width`/`thumbnail_height` on creative reads; the 64 px default is too small for dashboards.
- Persist IDs (creative id, `video_id`, `effective_object_story_id`), never CDN URLs. Resolve `/<video_id>?fields=source,picture` lazily and proxy/cache the bytes at fetch time; refresh = one ads_management call per video. For hot dashboards, a short-lived URL cache (hours) mirrors Meta's own expiry behavior; batch up to 50 video-node reads per HTTP request to cut latency, accepting that BUC accounting is unchanged.
- `RateGuard` already reads `x-business-use-case-usage`: parse the per-account `ads_management` entry and use `estimated_time_to_regain_access` (minutes) as the backoff signal; treat code 80004 as `rate_limited` alongside code 17/HTTP 429.
- Carousels/DPA: media lives inside `object_story_spec` (child attachments / `template_data`), so a creative-media feature needs to walk that spec, not just top-level `image_url`.
- Deep links into Ads Manager can be emitted for human workflows but must be treated as undocumented and tested against the accounts in use.
